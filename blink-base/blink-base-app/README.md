# blink-base-app

使用blink框架构建的RBAC后台管理服务。核心功能具有用户、角色、菜单、权限、组织管理功能。
其中菜单和权限分开独立，互不影响。

目前后端接口以实现，无前端界面
未来有时间用AI实现前端，或者有志同道合者前端开发者也共同参与blink-base的开发

## 功能

### 用户管理

用户是指后台管理人员，登入系统 操作或者查看业务数据。具有以下功能

- 用户分页列表：展示基本信息 可多条件查询

- 添加用户： 填写基本信息后 提交添加 其中可选分配角色，分配组织；如果用户无角色则 无法登入系统
  其中密码加盐加密
- 删除用户： 弹窗确认，目前数据库为物理删除，超级管理员不可删除
- 修改用户： 和详情页一致 提供基本信息修改 和组织 角色重新选择
- 用户详情： 比列表信息多出 组织和角色信息
- 分配组织： 弹窗组织以树形结构的形式展示提供选择 一个用户只允许选择一个组织，提供多用户批量分配
- 分配角色： 弹窗提供列表 搜索选择 可以选择多个角色 ，权限取多个集合并集  提供多用户批量分配


- 用户登入：用户通过登入名和密码登入，验证获取认证凭证（token）,本系统默认提供有状态token管理 后续可能添加jwt支持 可配置切换
  并且默认后台同时同一个用户只能登入一次，如果同一个账号重复登入，不是最新的登入会被踢出
- 用户锁定： 登入密码连续错误3次 自动锁定
- 登入用户列表：
  查看登入信息 提供强制下线功能

- 登出：删除凭证 退出登入
- 密码重置： 添加用户时密码加盐加密 无法还原 只能重新设置密码

### 角色管理

角色即用户拥有的身份，每个角色可配置关联菜单或权限。通过给用户赋予角色实现用户的权限控制和系统界面的显隐。

本系统角色分为系统内置角色和自定义角色

系统内置角色： 系统未投入生产就配置在数据库中的角色 比如超级管理员 系统管理员
自定义角色： 使用本系统创建的角色
关于超级管理员： 超级管理员具有系统的一切权限，但是它自身并不参与角色的管理（超级管理员只读性 只能有运维或者开发人员在数据库中配置）。所以它在系统中会特殊处理
               不保存任何超级管理员关联数据。超级管理员权限标识 *:**

- 列表 角色分页列表 提供角色基本信息 多条件查询 除了常规的条件查询 还提供按用户条件查询角色
    
- 添加角色 填写基本信息后 提交添加 其中可以为角色分配菜单或分配权限 
- 删除角色 角色物理删除，必须是当前未分配给任何用户的角色才可被删除 即存在关联用户的角色不可删除；而角色关联的权限 菜单一并删除
- 修改角色 修改基本信息后提交 包括重新分配菜单或权限
- 角色详情 比列表的基本信息 多了当前角色被分配的用户列表 角色具有的权限和菜单列表
- 分配菜单 分配可以展示的菜单 支持多角色批量分配
- 分配权限  分配可以访问的api权限和数据过滤权限 支持多角色批量分配


### 菜单管理

菜单保存的为系统前端页面的导航菜单和功能按钮，为了给不同角色的用户，做不同的菜单渲染。提供顺序、和显隐控制。
在本系统的设计中 菜单本身并不是权限，和权限独立分离，仅仅作为前端渲染控制。（这是在设计时容易混淆的地方 因为别的RBAC系统有菜单即权限的方案）

- 菜单树形列表 非分页 提供菜单基本信息 多条件查询
- 添加菜单 添加菜单时，尽量避免超过3层的深层菜单
- 删除菜单 物理删除 无法删除拥有子菜单的菜单
- 修改菜单 修改菜单基本信息 
- 菜单详情 查看菜单信息与列表信息基本没差别




### 权限管理

每个权限都具有唯一的权限标识 形式xxx:aaa:yyy
权限类型分为 接口权限 数据权限 

接口权限 对应的api接口 本系统全部采用post请求 所以接口权限的url应该具有唯一性 
        即url对与权限标识具有一对一关系，而权限标识对url 是一对多的关系 权限标识和url的关系是本系统接口鉴权的核心逻辑之一，不能动摇！

数据范围权限 属于数据纬度的权限控制 目前未实现 后续应该会使用mybatis-plus插件动态修改查询条件实现 
提供 时间范围过滤 数据字段过滤 敏感数据过滤 组别过滤等等常规规则



- 权限列表 分页 提供菜单基本信息 多条件查询
- 添加权限 添加菜单时，尽量避免超过3层的深层菜单
- 删除权限 无法删除拥有子菜单的菜单
- 修改权限 修改菜单基本信息
- 权限详情 查看菜单信息与列表信息基本没差别  



### 组织管理

组织对应现实公司部门、机构等。实际是对数据进行分组管理。属于数据范围权限维度； 本系统对组织的设计实现比较宽松，仅对组织抽象信息化。
并未添加过滤规则。一般会将组作为数据范围过滤规则之一 如不同组之间只能查看本组的业务数据。

- 组织树形列表 非分页 
- 添加组织 
- 删除组织 存在关联用户时 无法删除
- 修改组织 
- 组织详情
