# 单元测试规范

## 测试目的

**测试的核心目的是发现 Bug，而非单纯追求覆盖率。**

每完成一个模块的测试，必须输出：
1. 测试覆盖率报告
2. **Bug 清单**（如有）
3. 修复记录（如有）

---

## Bug 记录规范

### Bug 清单格式

在测试计划文档中，使用以下格式记录发现的 Bug：

```markdown
## Bug 清单

| 序号 | 发现时间 | Bug 描述 | 严重程度 | 文件位置 | 状态 | 修复说明 |
|------|----------|----------|----------|----------|------|----------|
| 1 | 2026-04-13 | xxx方法在xxx情况下NPE | 高 | XxxClass.java:35 | ✅ 已修复 | 添加null检查 |
```

### 严重程度定义

| 级别 | 定义 | 示例 |
|------|------|------|
| **高** | 导致系统崩溃、数据丢失、安全漏洞 | NPE、SQL注入、死锁 |
| **中** | 功能异常，但不会导致系统崩溃 | 逻辑错误、返回值不正确 |
| **低** | 不影响功能，但影响可维护性或用户体验 | 日志缺失、代码可读性差 |

### Bug 类型分类

| 类型 | 描述 |
|------|------|
| **逻辑错误** | 返回值不符合预期，条件判断错误 |
| **空指针** | 未检查 null 导致 NPE |
| **边界问题** | 边界值处理不当（如空集合、最大值、最小值） |
| **异常处理** | 异常捕获不当、日志信息不足 |
| **性能问题** | 循环嵌套过深、资源未释放 |
| **安全问题** | SQL注入、XSS、敏感信息泄露 |

## 测试用例设计原则

### 1. 必须覆盖的场景

- [ ] 正常场景（Happy Path）
- [ ] null 值处理
- [ ] 空集合/空字符串处理
- [ ] 边界值（最大值、最小值、临界值）
- [ ] 异常场景
- [ ] 并发场景（如适用）

### 2. 边界值测试清单

| 类型 | 边界值示例 |
|------|-----------|
| 整数 | 0, -1, 1, Integer.MAX_VALUE, Integer.MIN_VALUE |
| 字符串 | "", " ", 超长字符串, 特殊字符, 中文, null |
| 集合 | 空集合, 单元素, 大量元素, null |
| 日期 | 当前日期, 年初, 年末, 闰年, null |
| 小数 | 0.0, -0.0, 正数, 负数, 精度边界 |

### 3. 测试断言规范

```java
// 推荐：使用明确的断言消息
assertTrue(result, "当xxx时，应返回true");

// 推荐：使用 assertAll 分组断言
assertAll("日期范围校验",
    () -> assertTrue(validator.isValid(startDate, endDate)),
    () -> assertFalse(validator.isValid(endDate, startDate))
);

// 不推荐：无消息的断言
assertTrue(result);  // 失败时难以定位问题
```

## 测试流程

```
1. 分析被测类 → 列出测试场景
       ↓
2. 编写测试用例 → 执行测试
       ↓
3. 发现 Bug？ → 是 → 记录 Bug 清单
       ↓              ↓
      否           修复 Bug
       ↓              ↓
4. 更新测试用例 ← 验证修复
       ↓
5. 输出测试报告（含 Bug 清单）
```
